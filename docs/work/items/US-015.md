### US-015: Creating an experiment can never damage an existing one
**As an** operator, **I want** id reuse and filesystem-unsafe ids refused cleanly **so that** a create call can never destroy or corrupt an existing experiment's storyboard or row.
**Points:** 5
**Status:** Done
**Acceptance criteria:**
- [x] Given an experiment id that already exists, when POST /experiments is called with that id, then the API returns 409 and the existing row and storyboard file are unchanged (today the storyboard file is overwritten before a 500)
- [x] Given an id containing a Windows-invalid character (`:` `*` `?` `"` `<` `>` `|`), a reserved device name (e.g. `CON`, `NUL`, `COM1`), or a trailing dot/space, when creating any file-named entity (theme, niche, experiment), then the API returns 422 and no file or row is written
