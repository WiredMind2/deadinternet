### US-016: Validate tracked inputs at the API boundary
**As an** operator, **I want** snapshot, URL, offer, tracking-code, and render-cap inputs validated **so that** typos and hand-edited settings produce clear errors instead of silent orphans, broken redirects, and 500s.
**Points:** 5
**Status:** Done
**Acceptance criteria:**
- [x] Given a publication id that does not exist, when POST /snapshots is called, then it returns 404 and no snapshot row is written (today an orphan row is created and `{ok: true}` returned)
- [x] Given negative views, when POST /snapshots is called, then it returns 422
- [x] Given a post URL that does not start with http:// or https://, when POST /publications/{id}/url is called, then it returns 422 and the publication stays manual_needed
- [x] Given a post URL already stored for another publication of the same experiment, when POST /publications/{id}/url is called, then it returns 409 (today: 500 from the unique index)
- [x] Given a render_cap setting that is not a number, when GET /catalog or a render is requested, then the default cap applies with no 500
- [x] Given an own-offer with an empty offer_url, when POST /offers is called, then it returns 422 (today it is stored and /r/{code} redirects to an empty Location)
- [x] Given a tracking code already used by another experiment, when POST /experiments creates an experiment with that code, then it returns 422 (today clicks are attributed to an arbitrary experiment)
