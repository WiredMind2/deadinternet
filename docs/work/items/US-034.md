### US-034: Public read-only click app
**As an** operator, **I want** the `/r/{code}` redirect served by a separate public app that shares the store but exposes no admin routes **so that** clicks can be served to the open internet without exposing the lab's write surface.
**Points:** 3
**Status:** Done
**Acceptance criteria:**
- [x] Given the public app process, when any admin route is requested (experiments, results, suggest, and friends), then it returns 404
  — `tests/test_public_app.py::test_every_admin_route_returns_404_on_the_public_app` sweeps the admin app's own route table (every method and templated path, docs routes included) against the public app and asserts 404 for each; `test_the_public_app_has_exactly_one_route` pins the public surface to `GET /r/{code}` alone. Live-smoked 2026-11-19: `/experiments`, `/results`, `/suggest`, `/starter`, `/catalog`, `/offers`, `/snapshots`, `/themes`, `/docs`, `/openapi.json` all 404 on `python -m deadinternet --public`.
- [x] Given the public app, when `/r/{code}` is hit, then the click is logged exactly as the admin app logs it (same store, same counter+log transaction)
  — `tests/test_public_app.py::test_a_public_click_is_logged_exactly_like_an_admin_click` drives one store through both apps (a hit via the public app, then a hit via the admin app): same 302 destination, the shared counter reaches 2, the shared click log has 2 rows. Both routes call `hit()` from `track/redirect.py`, and `create_public_app` wraps the store in the same `_ThreadSafeStore` the admin app uses (imported from `api/app.py`, which is not modified).
- [x] Given an unknown code, when `/r/{code}` is hit, then the public app returns 404 without leaking store details
  — `tests/test_public_app.py::test_an_unknown_code_is_a_404_without_store_details` asserts the generic `unknown tracking code` detail, no counter change, no log row. The unconfigured-merchant path (`UnconfiguredDestination`, a KeyError subclass) mirrors the admin app's 404 and no-click effect while deliberately not naming the merchant or the `POST /offers` fix: `test_an_unconfigured_merchant_is_a_404_without_naming_it`.
- [x] Given the repo, when the public app is launched, then it runs as its own entrypoint (own process/port), separate from the admin API
  — `src/deadinternet/__main__.py`: `python -m deadinternet --public [port]` dispatches to `main_public()`, which opens the same `_db_path()` lab database, builds the public app, and serves 127.0.0.1:8001 (port by argument or `DEADINTERNET_PUBLIC_PORT`, host by `DEADINTERNET_PUBLIC_HOST`). Wiring mirrored from the admin's entrypoint tests: `test_main_public_serves_the_click_app_on_its_own_port`, `test_the_public_port_comes_from_the_argument_then_the_env`, `test_dispatch_serves_the_admin_by_default_and_the_click_app_on_public`. Live-smoked 2026-11-19 beside the running admin on 8000: both processes open the same sqlite file, which SQLite serializes with its default rollback-journal locking (WAL is not enabled in this codebase).
