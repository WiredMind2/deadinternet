### US-024: Every video gets its own tracking code
**As an** operator, **I want** each experiment to carry a unique tracking code from every creation path **so that** a click always credits the video that earned it, never a sibling or its parent.
**Points:** 5
**Status:** Done
**Acceptance criteria:**
- [x] Given a starter grid over two niches that share one tracking code, when the grid is built, then every draft ends up with a distinct code (today the two niches reuse the code and `add_click` credits an arbitrary row) — `test_starter_gives_every_draft_a_distinct_code_across_niches` (tests/test_api.py) recodes 4 drafts to `abc-2/-3/-avatar/-avatar-2` and credits one click per code to exactly the intended row
- [x] Given a suggested draft whose parent carried a tracking code, when the draft is created through the suggest/accept path, then the child's money carries a fresh code derived from the parent's (never the parent's exact code), so child clicks no longer credit the parent — `child_tracking_code` derives `abc-c2` (tests/test_proposal.py, tests/test_proposer.py)
- [x] Given any two creation paths (POST /experiments, POST /starter, proposer accept), when two experiments would end up with the same tracking code, then the second is refused or recoded, and a click on each code increments exactly the intended experiment — POST /experiments refuses the clash (422 naming the owner), the starter mints (`_mint_unique_tracking_code`), and the unique index backs both; a code that cannot be a URL segment (spaces, slashes) is refused up front on both routes, and an index clash reports "tracking code X is already used", not a phantom id conflict
- [x] Given a lab database that already contains duplicate codes, when the app upgrades, then startup does not crash and no existing rows are deleted (legacy rows may keep their codes; new creations must not add new duplicates) — `test_legacy_duplicate_tracking_codes_are_renamed_not_deleted` (tests/test_store.py): the earliest row keeps the code, later duplicates are renamed, and a new duplicate insert raises IntegrityError
